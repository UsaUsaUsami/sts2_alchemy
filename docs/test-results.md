## 2026-09-22: v0.7.0 エリート・ボスの素材報酬の検証

対象：ゲーム本体v0.111.0、BaseLib v3.4.5、.NET SDK 9.0.318。隔離実行環境`.research/runtime`（`scripts/smoke.ps1 -Name reward-slots -Frames 9000`）。

### ルール検証（`dotnet run --project tests/Alchemist.Core.Tests`）

220件PASS（v0.6.0の195件＋新規25件）。新規分：

- 枠数と候補数：エリート1枠・ボス2枠・各3候補。
- 抽選：3候補が相異なる／同じシードと枠IDで完全一致／シードと枠IDのどちらを変えても結果が変わる／400シードで4素材すべてが出現する。
- 枠の記録：同じIDは一度だけ／候補の重複・個数不正を拒否／未解決の枠がある間は錬成できない。
- 受け取り：候補外の素材を拒否／ちょうど1個だけ付与／二重取得を拒否／解決済みの枠は再提示されない。
- 辞退：枠が閉じる／二重辞退を拒否／辞退しても素材は増減しない。
- 満杯時：選んだ素材が`Pending`へ回り、交換で解決できる。
- 保存：未解決の枠と候補がセーブ・ロードを越えて残り、再提示されない。schema 1のセーブが素材を失わずに移行する。候補の破損、受領済みIDと未解決枠の矛盾を拒否する。

### 実機検証（隔離ヘッドレス、298件PASS、完了マーカー2種）

- 実際のエリート部屋・ボス部屋へ入り、敵を倒して`RewardsSet.WithRewardsFromRoom`＋`GenerateWithoutOffering`を通した結果、エリートに1枠、ボスに2枠の`MaterialReward`が入る。
- 既存報酬は残る：エリートでゴールド・カード・レリック、ボスでゴールド・カードを同時に確認。
- 報酬ラベルが日本語「素材を選ぶ」で表示される（BaseLibのrelicsロックテーブル経由）。
- 選択前は素材が増えない。撃破採取分とは独立。
- 報酬画面を作り直しても枠が増えず、候補も変わらない。
- 選択UIに3候補と辞退ボタンが表示され、選択後に該当素材がちょうど1個増え、報酬画面側の`OnSelect`が解放される。
- 受け取り済みの枠は再生成しても提示されない。
- 実際の`RewardsSet.Offer()`で報酬画面を表示した状態で、ボス2枠が`NRewardButton`として並ぶことを確認。
- 選択UIが`NOverlayStack`直下かつ報酬画面より後ろの子として追加され、前面に描画されることを確認（子インデックス比較）。
- ボス1枠を受け取った時点でレリックを直列化・復元し、残り1枠と未解決状態が保たれることを確認。残りを辞退すると解決済みになる。
